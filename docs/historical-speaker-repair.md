# 历史说话人修复记录

2026-10-11 的 HIS-01 审查发现，两份历史归档把正文中提及的人名误用为说话人姓名。部分润色字幕还重复插入了姓名前缀，派生摘要沿用了这些错误署名。

本次修复已在本地资料库完成：

- 将 155 处无证据支持的姓名标签恢复为原说话人编号，保留 150 处已有证据支持的标签。
- 将另一份归档的三组错误标签（1、5、3 处）恢复为原说话人编号。
- 仅移除逐条核对过的 39 个重复前缀，并修正四处派生文本中的错误署名。
- 同步修复字幕文件、JSON/Markdown 派生文件、SQLite 文本镜像和任务元数据。
- 保留原平台字幕。无法确认真实姓名的说话人继续使用匿名编号，质量状态标记为需要复核。

## 修复与恢复要求

同类修复必须先停止写入该资料库的进程，再预览目标文件、字幕序号、原文和预计修改次数。正文中出现的人名不能单独作为说话人身份依据。不要对整个归档执行姓名全局替换。

修改前备份数据库和所有目标文件。备份清单应记录原文件、预期修改后内容和提交状态。修改脚本必须同时核对预期原文与修改次数；任一项不符时停止，不继续覆盖文件。

文件更新与数据库更新需要恢复日志。重启后先处理未完成的日志，再开放资料库。未提交的修复恢复为原内容；已提交的修复核对全部镜像和索引。重复执行已完成的修复应返回无待修改项。

任务结果中的路径必须通过资料库现有的路径编码接口写入。不要把解码后的绝对路径直接写回数据库，也不要重建或丢弃原有 `path_fields`。

## 本次验证

修复工具通过 14 项回归检查，覆盖修改次数不符、文件回滚、异常中断恢复、重复执行，以及使用实际任务结构保存路径。实际修复后，两条任务均能通过 TaskStore 正常读取；文件与 SQLite 镜像一致；归档索引已刷新；再次预览没有待修改项。

修复输入、用户资料、数据库与备份只保存在本地。此记录不包含个人媒体、任务标识、绝对资料库路径或用于定位个人内容的替换清单。
