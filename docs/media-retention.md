# 媒体保留与空间回收

默认策略为 `all`，生成的归档媒体保留。设置中的“默认媒体保留策略”用于下一次清理预览，修改设置后由用户选择归档执行。

文件页右键归档 →“媒体保留”：

- 保留全部：保留所有文件。
- 保留播放文件及文字、图片：清理已记录用途的转码、人声分离和识别分片，保留原始来源及播放文件。
- 仅保留文字、图片和封面：进一步清理归档内部已识别的来源/播放媒体。外部源文件和声纹样本保留。

下载、转码、UVR、VAD 在 `media_assets.json` 中记录相对路径、用途及重新生成所需来源。历史归档可由 metadata.file_path 识别明确的播放文件；其余未记录用途的文件显示“用途待确认”并保留。扩展名用于列出媒体，清理候选由用途决定。

归档必须完成且存在已持久化的正文。活动任务、暂停任务、上传中的归档受到保护。预览列出每项大小、用途、处理影响和恢复条件，执行仅处理此次预览选中的文件。执行前重新检查任务与上传状态，失败项可在后续预览中重试。

清理会更新归档媒体状态、任务结果中的已删除媒体路径和同步 revision。同步保留文本、图片、封面及现有传输协议。

CLI：

```powershell
mpp storage media 'D:/资料库/archives/归档' --policy playback
mpp storage media 'D:/资料库/archives/归档' --policy playback --apply
```

`--apply` 展示预览后确认执行；脚本可加 `--yes`。策略允许 all、playback、text，省略时使用设置。

HTTP：`POST /api/pipeline/media-retention/preview` 接收 `{path, policy?}`，`POST /api/pipeline/media-retention/apply` 额外接收从预览选择的 `files` 相对路径数组。返回实际回收字节数、失败项和剩余候选。

保留全部会增加中间媒体的存储占用。清理后的重新处理依赖保留的来源或备份，下载地址能否再次访问以来源网站的实际状态为准。
