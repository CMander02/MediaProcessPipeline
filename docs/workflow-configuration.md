# 音视频流程配置

在「设置 → 处理流程 → 默认流程」勾选新任务需要执行的步骤。
在「新建处理 → 处理流程」可以临时调整。本次调整对当前提交的所有来源生效，不改全局设置。
点击「恢复全局默认」可以取消本次调整。

音视频始终执行 ASR，并保存原始字幕及归档文件。可以独立关闭：

- 素材分析：从标题、简介和画面补充术语与人物线索。
- 人声分离：去除背景音乐。CPU 服务器处理长音频时建议关闭。
- 区分说话人：按声音分配标签；声纹匹配仍使用已有声纹设置。
- 说话人修正：用模型核对标签和姓名。
- 字幕润色、内容分析、摘要、思维导图、视频详情。

关闭全部可选步骤后，只进行素材准备、ASR 和归档。摘要和思维导图可以分别运行。
声学说话人分离仍需要配置可用的说话人模型。
文字和图文来源继续使用各自的处理流程。

任务创建时会保存完整流程。之后修改全局默认，不改变这些任务。
旧任务没有流程快照时，会在首次执行新版管线时读取默认流程并保存。
导入命中已有内容时，复用已有任务和文件，不用本次配置重做。

## API

全局设置使用 `pipeline_workflow`；任务覆盖使用 `options.workflow`。可选键：

```json
{
  "source_analysis": true,
  "separate": false,
  "diarize": true,
  "speaker_review": true,
  "polish": true,
  "analyze": true,
  "summary": true,
  "mindmap": true,
  "detail": false
}
```

任务可只传需要覆盖的键。后端会合并默认设置并保存完整快照。
流程不接受关闭 ASR 的键。配置了新流程的音视频任务忽略平台字幕，执行 ASR。
尚未配置新流程的旧 API/CLI 调用继续保留原来的字幕策略和旧选项。

## 长音频的人声分离

MPP 为 audio-separator 的 WAV 合并接口使用流式写入。
每次最多读取 65,536 帧，不再把所有人声片段反复拼接在内存中。
合并先写临时文件，成功后再替换目标文件。失败时保留原目标文件。
分离成功后记录人声文件名，恢复转写时优先使用同一个人声文件。
