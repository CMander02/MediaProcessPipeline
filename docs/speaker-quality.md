# 说话人处理与历史复核

2026-10-04 实现记录，2026-10-05 修订。适用于新任务及用户主动发起的人物复核。

## 2026-10-05 修订

- **按来源给声音起名。** 来源中的参与者有三类：标题联名（如【瓜熟迪落拉XEric Hovagim02】，期号会去掉）、出现在联名里的上传者（作主持人），以及来源资料中标明主持或嘉宾的人。对话里没有自我介绍时，模型按每个声音的说话占比、提问数、直接称呼的人和发言样例对应参与者。一个声音直接称呼某人（如“What's your opinion, Eric?”），就不会被命名为这个人。这样得到的名字在人物面板上标「推断」，悬停可看依据。
- **待定字幕自动归属。** 声学上某个声音占这条字幕 80% 以上、其他声音合计不到 1 秒时，直接归给它。其余由模型结合前后文判断，只能从这条字幕里听到的声音中选。平台字幕没有声学信息，从已有人物中选。模型判断不了时，占多数（≥60%）的声音拿到这条，仍不行才保留待定。决定写进 `speaker_review.json` 的 `resolved_unassigned`，恢复时直接重用。
- **疑似同一人的声音。** 同一任务里，匿名声音与另一个声音的声纹相似度达到「建议」阈值（默认 0.60）时，人物面板提示合并，不自动合并。文本模型不再判断两个声音是否同一人。
- **复核批次更稳。** 模型回答里个别无效条目只丢弃该条，不再让整批失败。
- **结果页。** 顶部的提示条和「人物复核」折叠栏已移除。人物面板显示待定段数，可逐段跳转，并提供「自动补全」。自动补全在任务完成后运行，判断待定字幕并给匿名声音起名，直接写入当前字幕；改过的名字保持不变，补全期间字幕被编辑则不覆盖。摘要和导图写于改名之前时，面板和摘要、导图页提供「更新摘要和导图」，字幕和人物保持不变。重新生成后提示消失。

接口：`POST /api/tasks/{id}/speakers/repair`，`{ "mode": "auto" }`。

## 新任务

1. 保留原始字幕的正文、时间和编号。平台字幕中的方括号不自动代表人物。
2. 视频候选取 8 秒、50%、90% 三张图。开场无效时补 45 秒；名单不完整时补 25%、75%。最多六张。纯音频跳过图片。
3. 全文分窗提取可核对的身份引文。全部选中图片、平台资料、引文及已有声音标签进入同一多图请求。超出预算时统一降低图片尺寸；仍超限则明确失败，不截掉后半段证据。
4. 推断人物归属，核对有依据的姓名。名单、声音绑定分别记录。被谈论者、账号运营者、画面中的面孔不单独构成声音绑定证据。
5. 人物阶段结束后润色，再生成分析、摘要和导图。总结后不再自动命名。

用户明确设置的 `num_speakers` 是硬约束。名单估计只作提示。超过 N 的结果不能作为整理字幕发布；少于 N 时保留现有结果并显示约束冲突。匿名声音计入人数；`unknown` 表示归属待定，不作为一个人整体改名。

混合发言段先按声学重叠和前后文判断（见上方修订），无法判断的才保持待定。声音事件使用开放描述和 `speech/non_speech/mixed/uncertain` 输出字段。字幕模型的事件判断不等于经过音频验证。

## 恢复与复核

人物检查点保存完整输入、模型和实际参数、提示词、成功目标编号、失败范围、人物表、run_id、attempt、触发来源。每批原子保存。恢复使用输入直接比较；不使用文件内容指纹。输出截断时有限缩小批次；单条仍失败则保留原文并记录失败。

结果页的“人物复核”提供：

- **重试未完成批次**：检查原始字幕、模型、参数、提示词及人数约束。成功批次保持不变。缺少可靠检查点的旧档不支持精确续修。
- **复核全部人物**：以当前字幕为基线生成候选。旧档没有字幕对应关系时，不把原始编号当作整理段落编号。
- **查看候选**：显示旧人物、新人物、时间和原文。候选需要在字幕编辑器中逐段确认。
- **从当前字幕确认人物**：按当前标签重建人物列表和计数，记录人工确认，并在记录中标明被取代的旧报告。

人物复核进入现有串行后处理队列。字幕及摘要不会被候选自动覆盖。原始到整理字幕的拆分、合并对应关系写入 `transcript_lineage.json`，估算时间另作标记。

编辑器保存携带打开时的原文。文件变化返回 409；收到新版字幕时保留未保存草稿。手动改名只更新明确人物字段，不替换正文中的同名话题人物。已有摘要和导图标记待更新。

当前字幕确认产生 `speaker_reconciliation.json`。多文件发布使用 `speaker_reconciliation.pending.json` 保存基线和新内容，metadata 最后写入。再次确认相同字幕可继续未完成发布；第三方冲突会中止。完成后保留 `speaker_reconciliation.backup.json`。SQLite 副本失败沿用 ArtifactStore 的修复方式。

接口：

| 方法 | 路径 | 用途 |
|---|---|---|
| POST | `/api/tasks/{id}/speakers/repair` | `{ "mode": "failed" 或 "all" }` |
| GET | `/api/tasks/{id}/speakers/repair-preview` | 读取候选 |
| POST | `/api/tasks/{id}/speakers/reconcile` | `{ "expected_srt": "当前字幕全文" }` |

## 本机开发验证

本地模型为 Qwen3.5-4B-Q8，复用 llama.cpp 和 mmproj。测试进程独立运行，结束时释放。测试只读取原媒体，产物保存在项目临时目录。

| 视频 | 多图结果 | 限制 |
|---|---|---|
| 青稞 145 | 提取“李一博”，人数估计 1 | 只验证参与者证据提取，不证明全文只有一个声音 |
| NVIDIA EP26 | 提取“Chris Benson”，人数估计 3，状态 partial | 其他姓名证据不足，不能视为完整名单 |

补采后的联合请求约 3.6 秒和 5.0 秒，不含模型启动、抽帧与全文证据提取。真实请求与假客户端测试均覆盖多张图片同请求输入。没有把视觉人数当作声学人数。

声学脚本：

```powershell
uv run --no-sync python scripts/evaluate_speaker_clustering.py "录音.wav" --count 2 --output tmp/speaker-evaluation/case
uv run --no-sync python scripts/evaluate_speaker_clustering.py "录音.wav" --count 2 --output tmp/speaker-evaluation/case --reuse
```

每份录音选 10%、50%、85% 附近各 60 秒。一次提取 embedding，再比较原生固定 N、最大簇初始化、差异初始化、k-means++，以及未知人数阈值的有限邻域。按整份录音划入开发集。

本机实际参数：centroid、min_cluster_size=12、threshold=0.7045654963945799。青稞 145 取得 166 个 embedding；NVIDIA 取得 178 个。阈值 ±0.04 的未知人数结果分别保持 1 和 2。固定 N=2、N=3 是约束压力用例，不是对这些采样窗口真实人数的标注。

NVIDIA 的 k-means++ 与原生固定 N 的 ARI 约 0.613；最大簇/差异初始化约 0.966。这是候选之间的一致程度，不是准确率。margin=0.1 时，部分候选约 75% 的 embedding 会变成待定。因此保留原有默认策略和阈值，没有启用新的自动置信度门槛。

尚缺人工逐时间标注，错归、漏检、误检及短真实声音保留率均未测定。固定窗口也不能保证覆盖 Chris 的短发言。独立声学重算入口和平台字幕的音频增强仍受这项验收门槛约束。清华旧档保持冻结，当前未创建新的清华验收任务。
